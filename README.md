# EARN IT · الخادم والمزامنة (الإصدار الرابع)

## التشغيل
المتطلبات: Node.js 22.13 أو أحدث (يستخدم `node:sqlite` المدمجة، بلا قاعدة بيانات خارجية).

```bash
npm install          # يثبّت jsdom لاختبارات الواجهة فقط
npm start            # http://localhost:8080
```

متغيرات البيئة:
- `PORT`: منفذ الخادم (الافتراضي 8080).
- `EARN_DB`: مسار ملف SQLite (الافتراضي `data/earn-it.sqlite`).
- `COOKIE_SECURE=1`: يفعّل علامة `Secure` على الجلسة. **فعّلها دائماً خلف HTTPS في الإنتاج.**

## كيف تعمل المزامنة
- كل حالة مستخدم محفوظة كوثيقة واحدة مع **رقم مراجعة (revision)**.
- الكتابة تشترط رقم المراجعة الحالي؛ إذا تغيّر من جهاز آخر يُرفض التحديث بـ`409` ويُعاد تحميل أحدث نسخة. لا توجد كتابة صامتة تمحو بيانات جهاز آخر.
- الخادم يتحقق من كل حالة قبل حفظها (`lib/validate.js`):
  - السجل المالي متسق: كل صف يساوي `before + amount = after`، والسلسلة متصلة، والرصيد يساوي مجموع السجل.
  - السجل **للإضافة فقط**: لا يمكن تعديل صف سابق ولا حذفه ولا إعادة ترتيبه (`ledger_rewritten`، `ledger_truncated`).
  - المدخرات متسقة مع الأهداف، ولا قيم سالبة، والحقول المجهولة مرفوضة، وصور الملف الشخصي يجب أن تكون data URL لصورة فقط.
- الإجراءات الحساسة تتطلب كلمة المرور: إعادة الضبط، استعادة نسخة احتياطية، حذف الحساب.

## الأمان
- كلمات المرور: `scrypt` مع ملح عشوائي، والمقارنة بـ`timingSafeEqual`، وحساب وهمي لموازنة زمن الرد.
- الجلسة: رمز عشوائي 256 بت يُخزَّن مجزّأً (SHA-256)، في كوكي `HttpOnly` و`SameSite=Strict`، وتنتهي بعد 30 يوماً.
- تحديد المحاولات: 20 محاولة دخول لكل IP وبريد كل 15 دقيقة.
- حماية الطلبات: JSON فقط (`415` لغيره)، وحد للحجم (`413`)، ورؤوس `CSP` و`nosniff` و`no-referrer`.
- الملفات الثابتة: قائمة بيضاء صريحة، وحماية من اجتياز المسار.
- `/api/*` لا تُخزَّن مؤقتاً في سكربت الخدمة، فلا تتسرب بيانات حساب إلى مستخدم آخر على الجهاز نفسه.

## القيود المعروفة (صريحة)
1. **السلطة المالية:** المتصفح ما زال يحسب المكافآت. الخادم يضمن أن الحسابات متسقة ولا تُعاد كتابة التاريخ، لكنه لا يتحقق بعد من أن كل مكافأة مستحقة فعلاً. الخطوة التالية: نقل عمليات المال (إكمال مهمة، شراء، إيداع) إلى نقاط نهاية على الخادم تحسب المبالغ بنفسها.
2. **نسيان كلمة المرور:** لا يوجد بريد إلكتروني، فلا يمكن استعادة كلمة مرور منسية. يحتاج خدمة بريد لاحقاً.
3. **لا يوجد سجل تدقيق (audit)** لعمليات الاستعادة وإعادة الضبط وحذف الحساب بعد.
4. **تحديد المحاولات في الذاكرة:** يعمل مع نسخة واحدة من الخادم فقط.
5. **CSP يسمح بـ`unsafe-inline`:** لأن الواجهة في ملف واحد. نقل السكربت إلى ملف منفصل يحذف هذا التساهل.
6. **`node:sqlite` تجريبية** في Node 22، وتطلع تحذيراً عند التشغيل.
7. **ميزات من النسخة المرفوعة لم تُنقل بعد:** التحديات الجماعية بثلاثة مقاييس، والأصدقاء، والمزادات، والمساعد المحلي بقواعد، واستمرار مؤقت التركيز بعد إعادة تحميل الصفحة، واستيراد نسخ النسخة القديمة (تُحذف منها الحقول غير المعروفة).
8. **إزالة الإطارات من المتجر:** الإطارات صارت إعداداً في الملف الشخصي (أزرق، بنفسجي، ذهبي)، وتُرحَّل الإطارات القديمة تلقائياً.

## الإنتاج
- ضع الخادم خلف وكيل HTTPS (Nginx أو Caddy)، واضبط `COOKIE_SECURE=1`.
- احتفظ بنسخة احتياطية دورية لمجلد `data/` (ملف SQLite وملفاته الجانبية `-wal` و`-shm`).
- شغّل نسخة واحدة فقط (تحديد المحاولات في الذاكرة).
